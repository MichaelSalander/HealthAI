# 健管师端与 Admin 后台规划

## 1. 选型结论

### 推荐基座：vue-pure-admin

仓库：<https://github.com/pure-admin/vue-pure-admin>

选择理由：

- Vue 3 + Vite + TypeScript + Pinia，与本项目技术方向一致。
- 基于 Element Plus，适合数据表格、复杂表单、抽屉、审核、权限管理等后台场景。
- 中文生态、文档与实际项目案例较多，后续招聘与维护成本较低。
- 项目采用 MIT License，允许商业项目使用，但需要保留许可证与版权声明。
- 已提供权限、路由、Mock、国际化、主题等后台基础能力。
- 项目活跃度与社区规模明显高于轻量模板，适合作为长期后台基座。

### 备选方案

| 项目 | 适合场景 | 不作为主选的原因 |
|---|---|---|
| `zclzone/vue-naive-admin` | 需要快速获得前后端样例、动态菜单与权限时 | 官方前端说明以 JavaScript 为主，与本项目 TypeScript 规范不完全一致 |
| `un-pany/v3-admin-vite` | 想要更轻量的 Element Plus 后台 | 需要自行补齐更多业务后台基础能力 |
| `dannyna/vue3-admin` / Vuestic Admin | 国际化、Tailwind 与现代视觉风格 | 中国大陆后台生态、中文资料和 Element Plus 业务组件不如推荐方案直接 |

本项目不直接复制任何模板的业务页面，只复用后台壳层、权限、布局、表格与表单能力。C 端 uni-app 保持独立。

## 2. 代码组织

建议后续调整为：

```text
HealthAI/
├─ apps/
│  ├─ client/          # 当前 uni-app C 端
│  └─ console/         # 独立 Vue Web 后台，基于 vue-pure-admin
├─ packages/
│  ├─ domain/          # 共享领域类型、枚举、金额工具
│  └─ api-contracts/   # C 端与后台共同使用的 API Contract
└─ docs/
```

第一阶段为了减少迁移风险，可以先在当前仓库新增 `console/`，C 端目录不改；后台稳定后再整理为 pnpm workspace。

## 3. 后台角色

### 健管师端

- 查看分配给自己的客户
- 查看客户健康档案、报告、指标、趋势
- 查看完整 AI Insight
- 管理咨询会话与服务记录
- 更新客户服务状态与跟进记录

### Admin 端

- 用户、健管师、主责分配
- 健管师分类、等级、认证
- 服务方案、增值服务、价格与上下架
- 首页入口、导航、运营文案与健康分类
- 订单、支付状态、佣金与结算
- AI Insight 配置、敏感内容审核与操作日志
- 角色、权限、菜单与系统配置

健管师只能访问被分配客户及其服务范围；Admin 才能修改全局配置、价格、商品与权限。

## 4. “所有内容可后台调整”的边界

### 必须后台可调整

- 首页 Banner、入口标题、副标题、排序、跳转目标、上下架
- 底部导航名称、图标、排序与显示状态
- 健康管理师 9 大分类：名称、图标、排序、启用状态
- 健管师等级、认证类型、展示标签
- 服务方案：名称、等级、周期、价格、权益、说明、上下架
- 增值服务：名称、价格、时长、说明、上下架
- 健康指标展示名、单位、参考范围、异常文案
- 健康结果基础解释、风险提示、免责声明
- 咨询常用问题、服务记录类型与状态文案
- 活动、优惠券、协议与帮助内容
- 后台角色、菜单与权限

### 不能由普通运营人员直接任意修改

- 金额分单位规则
- 支付成功、退款、结算状态机
- 权限校验与数据隔离规则
- 健康数据审计与隐私字段脱敏规则
- AI 专业结论的最终医疗责任边界

这些由后端规则与 Admin 高权限审核控制，后台只能配置经过校验的参数。

## 5. 配置驱动原则

C 端不得把可运营内容硬编码在页面中。页面只负责渲染 API 返回的配置：

```text
CMS/Config API
       ↓
Repository
       ↓
Pinia Store
       ↓
uni-app 页面 / 后台页面
```

即使第一阶段使用 Mock，也必须让 Mock Repository 返回与未来 API 相同的结构。

## 6. 后台页面拆分

### H 端：健管师工作台

- H-01 工作台概览
- H-02 我的客户
- H-03 客户健康档案
- H-04 AI Insight
- H-05 咨询与服务记录
- H-06 个人资料与认证

### A 端：Admin 管理后台

- A-01 用户与客户
- A-02 健管师与分类
- A-03 服务方案与商品
- A-04 订单、支付、佣金与结算
- A-05 内容、首页配置与健康指标
- A-06 权限、审计与系统设置

## 7. 实施顺序

1. 建立独立 `console/` Vue 3 + TypeScript + Vite 项目，并接入推荐后台壳层。
2. 先做 Mock 登录、角色切换、动态菜单与权限路由。
3. 完成 A-03 服务方案与价格管理，验证“后台改价 → C 端读取”的闭环。
4. 完成 A-05 首页与健康内容配置，验证“后台改文案/排序/上下架 → C 端展示”的闭环。
5. 完成 H-01～H-06 健管师工作台。
6. 完成用户、订单、佣金、结算与审计。
7. 最后替换 Mock API 为真实后端 API，不改页面业务接口。

## 8. 当前决策

当前先不把 `vue-pure-admin` 直接合并进 C 端；下一次实施会先建立独立 `console/`，避免 uni-app 与桌面后台的构建、导航和样式互相污染。
