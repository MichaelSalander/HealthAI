# Backend 開發規則

本目錄包含 HealthAI 後端 API 與未來的背景任務。

## 安全與權限

- API 預設需要認證，公開 API 必須明確標註。
- `customer` 只能讀取自己的資料。
- `consultant` 只能讀取被分配或被授權的客戶。
- `admin` 才能執行全局管理、派單與配置操作。
- 前端隱藏按鈕不能取代後端權限檢查。
- 健康報告、電話、Token、支付密鑰不得寫入普通日誌。

## API 與資料

- API 使用 `/api/v1` 版本前綴。
- 回應統一包含 `code`、`message`、`data` 與 `requestId`。
- 金額使用整數分。
- 時間以 ISO 8601 UTC 保存。
- 寫入操作需要冪等處理，避免重複預約、派單與訂單。
- 所有重要狀態變更必須寫入審計紀錄。

## 業務規則

- 派單前檢查在線、可預約、時段、容量與每日上限。
- 已額滿或暫停接單的健管師不可接收新派單。
- 預約需要鎖定容量，避免多人同時預約超賣。
- 未完成必要血液檢查時，回傳指定體檢中心導流結果。
- AI Insight 未審核前，不得作為客戶端最終專業結論。

## Provider

- OCR、AI、支付、微信登入、推播、語音都使用 Provider 介面。
- 每個 Provider 必須有 Mock 實作，方便測試。
- 業務層不得直接依賴第三方 SDK。

## 驗收

- 單元測試：業務規則與狀態機。
- API 測試：成功、錯誤、未登入與越權。
- 並發測試：同時預約、派單與容量鎖定。
- 敏感資料測試：資料隔離、檔案下載與審計紀錄。
